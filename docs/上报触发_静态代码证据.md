# 上报触发：静态代码直接证据（继续解混淆版）

## 1. 纠正：0x1807bdc70 不是 16 项表

之前只读取了前 16 项，结论错误。实际检查结果：

- `0x1807bdc70` 所在 `.data` 区域在第一个非指针槽前有 `0xBCB` 个连续模块内函数指针；
- 因此观察到的索引不是越界：

| 混淆索引 | 表项地址 | 实际目标 | 目标语义（静态） |
|---:|---:|---:|---|
| `0x44B` | `0x1807BFEC8` | `0x18001EBB0` | `mov rax,[rcx+0x10]; ret` |
| `0x184` | `0x1807BE890` | `0x180333FE0` | 返回混淆后的固定 dword |
| `0x6CD` | `0x1807C12D8` | `0x180334000` | 对象/状态包装函数 |

这证明发送调度的表驱动调用可以继续静态解析；不能再把索引超过 15 当成运行时表缺失。

## 2. 已找到的直接上报门

真实代码函数：`0x18019F1E0–0x1801A0EE9`。

### 第一层：输入对象非空

```asm
0x18019f22e  mov r14, rdx
0x18019f26b  test r14, r14
0x18019f26e  je   0x1801a0ea1
```

因此该路径的 `RDX` 参数为 NULL 时，直接跳过后续上报处理。

### 第二层：查找/状态解析成功且结果对象非空

```asm
0x18019f2ab  lea rdx, [rbp+0x28]
0x18019f2af  mov rcx, r14
0x18019f2b2  call [rsi + rax*8]       ; 运行时解析为 0x1801A1AF0
0x18019f2b5  test al, al
0x18019f2be  mov [rbp+0xa8], r14
```

`0x1801A1AF0` 的静态尾部为：

```asm
0x1801a1b53  mov edx, [global]
0x1801a1b59  mov rcx, [rsp+0x20]
0x1801a1b5e  test rsi, rsi
0x1801a1b61  je   0x1801a1b66
0x1801a1b63  mov [rsi], rcx
0x1801a1b72  cmp eax, edx
0x1801a1b74  setne al
0x1801a1b77  test rcx, rcx
0x1801a1b7a  setne cl
0x1801a1b91  and al, cl
```

即：状态返回值必须通过比较，且输出对象指针非 NULL。

### 第三层：对象字段比较

解析出来的比较函数 `0x1800A4430` 是：

```asm
0x1800a4430  cmp qword ptr [rcx+0x10], rdx
0x1800a4452  sete al
0x1800a4455  ret
```

这是直接的字段条件：`object->field_0x10 == expected_value`。

### 第四层：后续布尔谓词链

```asm
0x18019f36a  call [rbx+rax*8]
0x18019f36d  test al, al
0x18019f36f  jne  0x1801a0dd2

0x18019f3c7  call 0x1801a4750
0x18019f3cf  test al, al
0x18019f3d1  je   0x1801a0dd2

0x18019f474  call [rdx+rax*8]
0x18019f477  test al, al
0x18019f480  jne  0x18019f48f
0x18019f486  call 0x1801a4cf0
0x18019f48b  test al, al
0x18019f49d  je   0x18019ff90
```

这些是实际控制流条件，不是基于时间间隔的推测。

## 3. 最终发送回调门

```asm
0x1801a0dd5  mov eax, [0x18073a844]
0x1801a0ddb  cmp eax, 0xdc432353
0x1801a0de0  sete sil
0x1801a0e85  test sil, sil
0x1801a0e92  je   0x1801a0ed5
0x1801a0e94  mov eax, [0x18073a84c]
0x1801a0e9a  cmp eax, 0xa3442ecc
0x1801a0e9f  jne  0x1801a0ed5
0x1801a0ed3  call [rax]
```

磁盘静态值恰好为：

```text
[0x18073A844] = 0xDC432353
[0x18073A848] = 0x7FE5DE6C
[0x18073A84C] = 0xA3442ECC
```

所以这几个比较是当前镜像下恒真的完整性/不透明谓词门，不应被解释成“检测类别阈值”。真正具有业务意义的是前面的对象非空、查找成功、对象字段匹配和后续 AL 谓词链。

## 4. 严格结论

静态代码已经直接证明：

1. 上报必须先进入 `0x18019F1E0` 这条状态/对象处理路径；
2. `RDX != NULL` 是第一条明确门；
3. 内部查找必须成功并产生非空结果对象；
4. 至少一个对象字段比较 `object+0x10 == expected` 和后续布尔谓词必须通过；
5. 所有谓词通过后，才执行尾部间接调用，动态栈验证该调用链最终进入 `0x1803CD330` → `0x180332770` → WinHTTP；
6. 时间间隔只能说明捕获中出现 burst，不能替代上述静态条件。

尚未完成的是把 `0x1801A3F10` / `0x1801A4410` / `0x1801A4750` 内部的对象类型和每个混淆表项全部命名；但它们的控制流谓词位置已经恢复。
