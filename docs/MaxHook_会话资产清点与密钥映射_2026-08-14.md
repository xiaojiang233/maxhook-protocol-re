## 二、本轮新确认

1. **`crypto_capture2`（pid 16448）= verify-set 会话**：keyread hook `0x180322e30` 抓到
   48B = `input32(16B) + input64(32B)`，其中 input64 = `30BFEAFE...0345`，与
   `crypto_verify_set.json` 的 `key_material_64hex` 完全一致。7 个 nonce 也全部捕获
   （`f5cb4fb1...`/`8a39a903...`/`2169d293...`/`feef5fe9...`/`cadb4a27...`/`c174c224...`/`1d15e6ab...`）。

2. **`encrypt_boundary_capture` 与 `encrypt_boundary_capture2` 是同一会话（pid 46460）**，
   4 调用同 key `9626DA95...9D40`，4 nonce（`5cf37d90...`/`f66ba350...`/`d5d58db6...`/`4161c9f1...`），
   完整 (pt, ct, tag)。此为**第一个同 key 多 nonce 完整输出**的会话。

3. **nonce 混合非弱加性**（`analyze_boundary2_session.py`）：`KS1^KS2 ≠ N1^N2`
   （`b0aacc08...` vs `aa98dec0...`），进一步证实密码是**强 nonce 混合的 ARX 流密码**，
   非弱加性 nonce 混合。

4. `encrypt_boundary_capture2` 的 `context_dump.bin`（256B）是 **report-builder 对象**
   （含 "session_id"/"device_id"/"seq"/"timestamp"/"nonce" 字段名），**非 VM 密码 context**。
   `mat_context` 的 `context=0xeda58fee78` 是 encrypt 函数 R9 参数（对象指针），非 VM context。

## 三、可复现性结论（精确）

- **信封 + 函数签名 + key/nonce/tag 布局**：100% 已复现（多会话一致验证）。
- **流密码结构**（key-schedule ARX 循环 + 明文生成器 + fold + store32 + 全部常量）：
  100% 离线已解（第 99-100 轮）。
- **密钥流逐字节复现**：需要 (a) key 字节 + (b) key 派生 S-box 内容。目前**没有任何单一
  会话同时捕获这两者**：verify-set/writer_sync/encrypt_boundary2 有 key+明密对但无 VM context；
  keystream_history 有 VM context 但无 key 字节。
- **校验能力**：一旦 fold 闭式被符号执行得到，可用 7(verify) + 3(writer_sync) + 4(boundary2)
  共 **14 组已知 (key, nonce → keystream) 对**做 14/14 校验（远超原来的 7/7）。
