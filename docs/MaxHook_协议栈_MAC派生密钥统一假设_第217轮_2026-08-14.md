# MaxHook 协议栈 — MAC 派生密钥统一假设（第 217 轮）

日期：2026-08-14
范围：纯离线

## 一、核心结论：keystream 与 tag MAC 共享同一个 key-schedule

第 217 轮通过 10 组（同 key `32206F9C...`、10 nonce、10 tag、10 ct）的系统性 MAC 假设测试
（`test_mac_systematic.py`，~90 种构造），**全部不匹配**，证明：

> **tag MAC 的密钥不是原始会话密钥（input64 的 32B），而是 key-schedule 派生的密钥。**

这统一了整个剩余缺口：

```
key(32B) + nonce(12B)
   └── key_schedule_expand(key, nonce)  ← 唯一剩余项
         ├── keystream = ARX 流密码(state)     → ciphertext = plaintext XOR ks
         └── MAC key = derived_key(state)      → tag = SHA-256(derived_key, msg)[:16]
```

即：**keystream 与 tag 两者都收敛于同一个 `key_schedule_expand()`**。一旦复现它，
包体加密（keystream）与完整性（tag）可同时闭合。

## 二、证据链

1. **SHA-256 确认**（第 216 轮）：IV 常量 `0x6a09e667`...`0x5be0cd19` 由 `0x18042b970`
   写入 112B SHA-256 上下文（`encrypt_vm_clean_complete.json` inst 4149897）。
2. **SHA-256 初始化时机**：加密流程末尾（4.15M/4.16M 指令），在 nonce 写入（`0x20000100080`）
   之后——即 ciphertext 生成后计算 tag。
3. **~90 种 MAC 假设全不匹配**（`test_mac_systematic.py`）：HMAC-SHA256 用原始 key ×
   8 种 key 派生 × 6 种消息顺序 + SHA-256 长度编码变体 + nonce 作 key + HKDF-like 双层 HMAC，
   全部 0/10 匹配。
4. **nonce 非 SHA-256 派生**（`test_nonce_sha256.py`）：nonce 是内部 CSPRNG，非 key+counter 哈希。

## 四、剩余精确缺口（唯一，已收敛）

**`key_schedule_expand(key, nonce)`**：key 已定位其消费者（memcpy `0x1805d0c36` inst 1403261
读入），nonce 缓冲 `0x20000100080` 已定位。剩余是追踪 key+nonce 在 VM 状态槽中的 ARX 展开，
产出 keystream + MAC key。
