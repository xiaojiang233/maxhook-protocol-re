# MaxHook 协议栈 — 剩余缺口精确定位（第 222 轮）

日期：2026-08-14
范围：纯离线

## 一、精确定位 divergence 点：nonce 生成（VM 数据栈未捕获）

第 222 轮通过分析 `encrypt_vm_clean_complete.json` 的最后指令序列，精确定位了离线 emulation
的 divergence 点：

```
最后指令：
  0x180c25d9c: jmp 0x180c25a53
  0x180c25a53: ret
  RIP -> 0x7ffe1feeb8 (栈地址，非 handler 地址)

此时寄存器：
  rdi = 0x20000100080   (nonce 缓冲, 12B)
  rsi = 0xc             (12 = nonce 长度)
  rcx = 0x8
  rdx = 0x361a8e81
```

**根因**：VM 的 return-oriented dispatch 从 `[rsp]` 弹出下一个 handler 地址，但得到的是**栈地址**
`0x7ffe1feeb8`（而非 `.bugland` handler 地址）——即 VM 的**数据栈**（在 native 栈上）被污染/未正确
种子。此时 VM 正要做 **nonce 生成**（`rdi`=nonce 缓冲，`rsi`=12）。

## 二、缺失的数据：vm_enter_stack（8704B）

`vm_context_capture2` 的 `vm_enter_stack` 事件记录了 VM 数据栈地址 `0x86dfff0f8`、大小 8704B、
`rsp_at_capture=0x86dfff2f8`，但**没有 `file` 字段——栈内容未被保存**（已核实）。

这个 8704B 的 VM 数据栈包含：
1. CSPRNG 状态（nonce 生成所需）
2. handler return 地址（VM return-oriented dispatch 所需）

缺失它，导致 nonce 生成后的 dispatch 无法继续。

## 三、结论：剩余缺口的精确定义

| 项 | 状态 |
|----|------|
| 协议结构（信封/双组件密码/常量/槽位/缓冲布局） | ✅ 100% 复现 |
| key-schedule INIT + rolling key | ✅ 离线执行忠实（`0x2dba4ba`/`0xadeb35f2` 匹配） |
| key 消费者 + nonce 指针 | ✅ 定位（memcpy `0x1805d0c36` / context +0x61） |
| nonce 生成（VM CSPRNG） | ❌ 需 VM 数据栈（8704B，未捕获）或种子 ground-truth nonce |
| keystream 生成（ARX 循环 → store32） | ❌ 需 nonce + 完整 key-schedule |

**剩余精确步骤**（确定性、纯离线）：
1. 用 ground-truth nonce（vm_context2 call1=`c38d500ac2ae8d2611ae1749`）种子 nonce 缓冲；
2. 修正 harness 误报完成检测（RIP 离开模块 ≠ 完成，VM 用 return-oriented dispatch）；
3. 继续执行到 store32 → keystream → 与 ground-truth 校验。
