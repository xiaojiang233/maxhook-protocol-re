# MaxHook：纯离线差分定位 32-byte key absorption round

日期：2026-08-14

## 边界

本轮没有连接或注入真实进程。全部结果来自本地 dump、Unicorn replay 和两次离线输入差分。
端到端 keystream/tag 仍未闭合。

## 1. 离线差分运行已加速

`emulate_maxhook_encrypt_boundary.py` 新增 `--fast-diff-trace`：

- 只加载已证明足够的 16 个 module overlays；
- 不再读取 5.7GB、10764 个无关 heap dump 文件；
- 只在已知 VM indirect-jump source 记录 context/stack/registers；
- 关闭高开销的通用 memory logging。

结果：

```text
2 x 1,500,000-instruction differential replay: 约 18 秒
2 x 2,000,000-instruction differential replay: 约 22 秒
```

## 2. decoded key 的真实离线数据流

64 个 ASCII hex 字符仍先解码为 32 bytes：

```text
heap decoded-key buffer = 0x200001000e0
```

第一次读取 decoded key：

```text
instruction = 1,404,053
0x1805d0c36 movdqu xmm1, [rdx]
0x1805d0c3a movdqu xmm2, [rdx+r8-0x10]
source      = 0x200001000e0
bytes       = 32
```

随后复制到 VM/native stack：

```text
destination = 0x7ffe1fec70
0x1805d0c41 movdqu [rcx], xmm1
0x1805d0c45 movdqu [rcx+r8-0x10], xmm2
```

## 3. 32 次逐字节吸收轮

基线 key：32 bytes `bb`。离线变体分别修改 byte 0、1、2、31 的最低位。
四组实验均证明：

```text
round count                  = 32
VM jumps per key byte        = 26
native instructions per byte = 14,070
producer target              = 0x18098abf8
producer body                = 0x180aa57d7
producer VIP                 = 0x181be1445
key-byte pointer slot        = ctx+0x45
injection slot               = ctx+0x0e
```

每轮开始时：

```text
ctx+0x45 = 0x7ffe1fec70 + key_byte_index
```

直接读取和注入：

```text
0x180aa5b9f mov rax, [ctx+0x45]
0x180aa5bba mov al, [rax]
0x180aa5bca movzx r10d, al
0x180aa5bce mov dword [ctx+0x0e], r10d
0x180aa5bd8 mov dword [ctx+0x12], 0
```

即每轮先把一个 key byte 零扩展为 qword 状态：

```text
ctx[0x0e:0x16] = uint64(key[index])
```

## 4. 差分时间公式

第 0 个 key byte 首次影响 VM context：

```text
instruction 1,422,141
```

任意 byte `i`：

```text
first_influence_instruction(i) = 1,422,141 + 14,070 * i
```

已验证：

```text
byte 0  -> 1,422,141
byte 1  -> 1,436,211
byte 2  -> 1,450,281
byte 31 -> 1,858,311
```

## 5. 控制流不受 key bit 影响

四个 key 变体中：

```text
source sequence: identical
target sequence: identical
VIP sequence:    identical
rolling dispatch key sequence: identical
```

说明当前 key schedule 是固定 26-handler round，key 改变数据状态，但不改变该轮控制流。

## 6. key byte 的首轮传播槽位

byte `i` 首先进入 `ctx+0x0e`，随后传播到：

```text
ctx+0x10e
ctx+0x16f
ctx+0x152
ctx+0x15a
stack byte 0x90+i
stack byte 0x50+i
```

首个直接 producer：

```text
target = 0x18098abf8
body   = 0x180aa57d7
```

它内部按顺序执行三个 inner handlers：

```text
index 0x264 -> body 0x180aa57d7
index 0x409 -> body 0x180b39a1c
index 0x471 -> body 0x180b6d3bf
```
