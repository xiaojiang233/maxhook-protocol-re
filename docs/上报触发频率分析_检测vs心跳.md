# 上报触发频率分析：检测触发 vs 周期心跳

## 结论
**用户质疑正确：上报不是均匀周期心跳，而是"~30s 低频率基准心跳 + 检测到异常时的爆发式快速上报"。**

## 证据（8 个 capture，36 个间隔）
- LONG (~30s): 6 个间隔，全部 25.4–30.0s，几乎精确锚定 ~28–30s = **基准周期**
- MID (3–20s): 9 个间隔，9.8–22.2s
- SHORT (<3s): 21 个间隔，0.0–1.7s，均值 1.04s = **检测触发爆发**

## 结构模式
每个 capture 内部呈固定配对：
```
seq75→76  30.0s   <- 基准心跳
seq76→77   1.5s   <- 检测触发 burst
seq77→78   0.3s   <- 紧接密集上报
seq78→79  28.2s   <- 恢复基准
seq79→80   1.5s   <- 再次触发
```

## 含义
- 这些 capture 记录的高频 seq 连续上报，是**检测到事件/风险后的补偿性快速上报**，不是恒定每 3s 心跳。
- vm_context_capture2 rpt 特别大（7084, 2898 bytes）→ 检测到异常时上报内容更大更详细。
- **对 tag 恢复的含义**：tag 阶段可能也在这些异常路径中；检测触发时可能使用不同的上下文/附加数据拼进 MAC 输入，这正是"标准 MAC 构造 0 命中"的潜在原因——不是算法变体，而是**触发路径不同导致输入拼装含额外字段**（如检测类别、风险标记）。
