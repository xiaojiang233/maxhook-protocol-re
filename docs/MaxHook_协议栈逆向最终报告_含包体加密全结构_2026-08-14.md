## 1. 协议信封与加密函数

### 1.1 信封

```text

输出对象 = 4 连续 MSVC std::string：
```

### 1.2 加密函数签名 `0x180324610`


**nonce 是输出而非输入**：12B nonce 由内部 CSPRNG 随机生成，非 key 的哈希（证伪 MD5/SHA1/SHA256/SHA512(key) 前缀）。

## 8. 精确剩余障碍（第 11 轮最终诊断）

1. **dump 是"空闲态"**：`dump_out/41264` 的 context 是进程空闲时的残留态，不含"某次进行中加密"的
   key-schedule 状态。key/nonce（synthetic input64/input32）虽被正确写入 heap 并被 VM 消费
   （`rdi=0x20000100080` = key buffer +0x80），但 VM 的 key-schedule 字节码期望的是跨调用保留的
   **已解密 context 状态**，而 dump 的 context 是空闲态，导致：
2. **`context+0x61`（keystream 状态表指针）指向错误地址**：应为 `0x180835f10`，但空闲态下指向
   `0x1efa1952d10`（Java 堆，未映射）→ `0x180a831db mov r15d,[r15]` 读不到密钥流字；
3. **字节泵 `0x180bd46b1` 死循环**：VM 在 key-schedule 字节码中循环（2M 指令仍未产出 store32），
   因为空闲态 context 的状态机不收敛到 keystream 生成。

**结论**：fold 闭式需要**"进行中加密"的运行时 context**（含正确 key-schedule 状态），而本地 dump 是
"空闲态"。这是纯数据缺口（非代码缺口、非必须真机 Hook）：fold 代码 100% 离线可读、常量已全部识别，
只缺一组 (6 槽值, EDX 输出) 的同瞬时匹配样本。若本地有"加密进行中"的 dump（而非空闲 dump），
即可立即闭合 fold 并用 10 组已知明文对 + 7 验证集样本做 7/7 校验。

## 9. 密码强度密码分析（第 12-13 轮，负结果均确认密码强度）

1. **无简单 2 槽 fold**（`bruteforce_fold.py`）：在 52 个快照上穷举所有 (槽i, 槽j, add/xor/sub)
   组合，最大命中 2/48（= 偶然），证明 fold 是**高阶非线性**（3+ 槽 + shr/shl/not/neg + 常量）；
2. **无加性 nonce 混合**（`differential_nonce.py`）：同 key 三 nonce 的密钥流 XOR 不等于 nonce XOR
   （`KS1^KS2 ≠ N1^N2`），且密钥流差高熵（前 64 字节 61 个不同值），证明 nonce 经完整 ARX 轮函数混合，
   非弱加性混合；
3. **无初始态泄漏**（第 4 轮）：密钥流从第 0 字节起完全扩散；
4. **已证伪 1508 项标准原语**（AES/ChaCha/Salsa/BLAKE/HMAC/RC4/SM4/RC5/6 等 0 命中）。

综合：密码是**正确设计的定制 bytecode-compiled ARX 流密码**，全量复现需执行 VM 字节码（障碍 =
空闲态 dump 缺活态 key-schedule 状态）。

5. **无简单递推**（`test_recursive_generator.py`，第 17 轮）：186/338/281 个 ground-truth 密钥流字
   无一致的 `w[n+1] = rol(w[n]) ^ const` 递推（每个 (rotation, const) 仅出现 1 次），证明每字独立
   由 `F(key_schedule_state, counter)` 产生，非滞后生成器（非 xorshift/LFSR/递推流密码）。

## 11. 离线重放的最终状态（第 28-29 轮工程进展）

1. **修复 region 映射 bug**（第 28 轮）：`emulate_maxhook_encrypt_boundary.py` 的 `--dump-dir` 加载

   `0x1efa1952d10` 崩溃。修复后（对 `>=0x1ef0000000` 堆 region 先 `mem_map`），重放从 1.29M 推进到

2. **确认 VM 字节码加密**（第 26 轮）：16-bit 字节码字用 rolling key 加密
   （`real_index = (word - key + 0x5214a88c) & 0xffff`），小值=context 槽偏移、大值=加密 opcode；
3. **确认 rolling key 与 keystream 分离**（第 27 轮）：rolling key 在 dispatch 阶段前进，XOR 时刻稳定

4. **最终确认**（第 28-29 轮）：字生产者 156 次命中全是 key-schedule 阶段（fold 仅命中 2 次且
