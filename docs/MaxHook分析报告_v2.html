执行摘要

1. MaxHook.dll 是 WinLicense（Themida）加壳的 JVMTI/JNI 原生反作弊，随 heypixel mod 分发（jar 内 lib/MaxHook.x64.dll），与「布吉岛」服务器同厂商（开发路径 NativeAntiCheat\x64\Release\anti-cheat.dll）。

2. 检测面两层：① Java mod（ZKM 混淆）经 heypixel:s2cevent 上报 mod 哈希 + 硬件指纹（jasypt 加密），含 SyncToken 心跳；② DLL 经 JNI 钩子（jni_call_hook::flush_and_report）挂钩 net/minecraft* 类、自带 socket 层 + 内嵌 Certum/Sectigo 证书库经 WinHTTP 独立上报。

3. 根因（「协议无效」）：跨服 GAME→CONFIGURATION 重协商后，代理代答配置阶段导致 heypixel 通道重注册与完整性/心跳链路断裂，服务端周期校验缺失 → 周期判「协议无效」。

4. VM 攻破状态：解压 100% 还原（与真机 dump 99.99% 一致）；VM 初始化已绕过（预填真机上下文后 VM 正常执行 13 块）；卡在 VM 读取真机 VirtualAlloc 堆数据（runtime dump 无堆内容）——需真机全进程内存 dump 才能继续。

5. 已交付明文区反汇编：原始 .text（175 万行）+ 解压区（67.7 万行）+ 字符串表（4.5 万条）。

一、壳结构与解压还原

  • WinLicense 特征：入口 RVA 0x1F00058 位于 .boot 节（15.9MB，熵 7.95）；明文特征串 WinLicenseVersion/WinLicenseDriverVersion//forcerun//dumpstatus、注册表 SOFTWARE\WinLicense/Software\WLkt。
  • 解压流程（Unicorn 完整还原）：入口 LZ77 stub（src=base+0x1F00248，dst=base+0x980000=.bugland）→ helper 计算 delta → 循环解压 22.5MB → jmp base+0xC0EB27（真实入口）。解压产物 boot_unpacked.bin 与真机 runtime dump 99.99% 一致，解压实现已验证正确。

五、代理链路与根因

  • 代理（S1mple/MCProtocolLib 1.20.6）：GAME 态全转发；跨服重协商走 legacyServerSwitch 代答配置阶段。
  • 代理源码注释自认："Dropping them makes the server judge the client's protocol invalid (missing integrity report / sync token) after the switch"。
  • 触发链：跨服后客户端（GAME 态）不重发 minecraft:register → 新上下文无 heypixel 通道注册 → 完整性上报/心跳断裂 → 周期判「协议无效」。DLL 不校验 Minecraft 连接对端 IP（校验的是自己 WinHTTP 通道的 TLS 对端）。
  • 3h 运行日志：s2cevent 2.5 万次、sync_skins 2042 次，无 WARN/ERROR——流量正常，判定在服务端。

6.2 硬卡点：真机堆数据缺失

VM 读取 真机 VirtualAlloc 分配地址（如 0x1AB783620D0、0x20088C8F8）。这些堆内容不在 runtime-unpacked dump 里（该 dump 只有模块映像 + 解压区）。模拟堆为空 → VM 读 0 → 指针错 → INSN_INVALID。

结论：无真机堆 dump，VM 无法继续。需朋友用 VMMap / Process Hacker 全进程内存 dump（含 VirtualAlloc 区域）→ 重定位堆指针 + 填入内容 → VM 可跑到 OEP 解密字符串。

6.3 工程教训

  • unicorn 2.1.4 在 Windows 不稳定：emu_start 偶发立即返回/卡死；循环创建 Uc 实例全失败（全局状态污染）→ 必须独立进程。
  • PHASE1 解压偶发失败（rax≠期望值）——因 unicorn 内存初始态不确定，曾误导为解压错误。
  • 若干「崩溃」实为 Python 异常（如 struct.pack('<I', -480) 负数溢出）被误判为 unicorn 崩溃。
  • 范围 code hook 在 unicorn 2.1.4 对范围内每条指令触发（非仅 begin 处）——回调必须精确过滤地址。
