# MaxHook 协议栈 — SHA-256 组件发现（第 216 轮决定性突破）

日期：2026-08-14
范围：纯离线（Unicorn 具体执行 + heap write 追踪 + 静态反汇编）

## 一、决定性发现：协议使用 SHA-256

此前 215 轮的结论是"定制 ARX，无标准密码算法"。第 216 轮通过 `encrypt_vm_clean_complete.json`
（4.16M 指令离线具体执行产物）的 **heap write 追踪**，发现：

**SHA-256 初始哈希值（IV）常量被写入 heap 缓冲**：

| 地址（heap 偏移） | 值 | 含义 |
|-------------------|-----|------|
| `0x200001000f0` | `0x6a09e667` | SHA-256 H0 |
| `0x200001000f4` | `0xbb67ae85` | SHA-256 H1 |
| `0x200001000f8` | `0x3c6ef372` | SHA-256 H2 |
| `0x200001000fc` | `0xa54ff53a` | SHA-256 H3 |
| `0x20000100100` | `0x510e527f` | SHA-256 H4 |
| `0x20000100104` | `0x9b05688c` | SHA-256 H5 |
| `0x20000100108` | `0x1f83d9ab` | SHA-256 H6 |
| `0x2000010010c` | `0x5be0cd19` | SHA-256 H7 |

写入 RIP = `0x18042b970`（指令 4149897-4150170），为标准 FIPS 180-4 SHA-256 IV，**逐字匹配**。

## 二、完整 heap 分配布局（加密流程输入结构）

`encrypt_vm_clean_complete.json` 的 allocations 字段揭示加密流程的**全部缓冲布局**：

| 地址 | 大小 | 语义 | 证据 |
|------|------|------|------|
| `0x20000100000` | 32B | **解码后的 key**（input64 hex → 32 字节） | memcpy 逐字节写（inst 313473-327876），inst 1403261 被 `0x1805d0c36`(memcpy) 4×8B 读走 |
| `0x20000100030` | 32B | **AAD 字符串** `v3\|hpac.v3.session.report.req`（27B） | inst 976793 memcpy 写入 |
| `0x20000100060` | 16B | **kid**（input32，`35C98BC0...` 16B） | inst 3594848 写入 |
| `0x20000100080` | 12B | **nonce**（12B，内部 CSPRNG） | 本 run 未写（nonce 在 key-schedule 中生成） |
| `0x200001000a0` | 112B | **SHA-256 上下文**（state 在 +0x50） | inst 4149897 起写 IV |

## 三、加密流程数据流（第 216 轮重构）

```
1. input64 (64 hex chars) --hex decode--> key (32B) @ 0x20000100000   [明文, inst 313K]
2. key (32B) --memcpy @0x1805d0c36--> key-schedule 状态                 [inst 1403261]
3. AAD "v3|hpac.v3.session.report.req" --构建--> 消息缓冲               [明文, inst 976K]
4. kid (16B) + nonce (12B) --组装--> 消息
5. 定制 ARX 流密码（VM）--keystream--> ciphertext = plaintext XOR ks
6. SHA-256 (init @0x18042b970, inst 4.15M) --> tag (16B MAC)
```

## 四、对既有结论的修正

| 旧结论（第 103 轮） | 修正（第 216 轮） |
|--------------------|------------------|
| "纯 ARX，无 S-box，无标准算法" | keystream 密码是 ARX，但 **tag MAC 使用 SHA-256** |
| "tag = 16B MAC（构造未恢复）" | tag = SHA-256 派生（HMAC-SHA256 或 SHA-256 变体，精确消息布局待定） |

## 五、剩余精确缺口（进一步缩小）

1. **tag MAC 精确构造**：已排除 15 种简单 HMAC-SHA256/SHA-256 组合（`test_tag_sha256.py`），
   需追踪 SHA-256 update 的精确消息（可能含 key 派生 MAC key、长度编码、或 S2V 结构）。
2. **keystream 密码 key-schedule**：仍为 VM 表驱动字节码程序，key 经 memcpy 进入（inst 1403261
   已定位消费者），需追踪 key 在 VM 状态槽中的展开。
