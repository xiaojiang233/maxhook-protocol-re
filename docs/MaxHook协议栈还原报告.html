② key 吸收（VM key-schedule）✅ 完成

32 字节 raw key 在受保护的 VM 中经 64 固定轮（每字节 26 次 VM 跳转）吸收。 离线证明了吸收后的 key 依赖完全等价于：

array_a[i] = block[i] ^ 0x5c      # key || zero32
array_b[i] = block[i] ^ 0x36

用随机 00..1f key 对完整 context/stack/寄存器/VIP/dispatch-key/target 做全等验证，替代 1664 次 VM 跳转。

③ domain KDF（HMAC-SHA256）✅ 完成

通过 SHA 调用顺序和中间 digest 离线证明，derived key 精确为：

derived_key = HMAC-SHA256(raw_key, b"v3|hpac.v3.session.report.req")

模块的 SHA-256 在 emulator 中被逐段验证为完全标准（4 次 update 数据 = 标准 HMAC 的 inner/outer 序列），derived_key = 标准值（如 sample1 的 derived_key 前缀 2f0344…）。

④ payload 加密（ChaCha20）✅ 完成

精确为标准 RFC 8439 / IETF ChaCha20：

  • 20 rounds、32-bit counter、96-bit nonce、little-endian words
  • payload counter 从 1 开始
  • counter0 block（counter=0）在 payload 前生成（认证材料）
ciphertext = plaintext XOR ChaCha20(key=derived_key, nonce=nonce, initial_counter=1)

3. 未还原环节：16-byte tag（MAC）

⑦ tag 构造 ❌ 0/24

准确状态：independent tag = 0/24，mac_tag() 保持 fail-closed （抛 NotImplementedError）。未用捕获的 tag 伪装成实现，未宣称完整复现。

已确认的事实

  • tag 值是可信的：crypto_verify_set 与 crypto_capture2 两处来源完全一致（7/7 MATCH）
  • 模块 SHA-256 是标准的：emulator 内逐段验证 KDF 的 4 次 SHA update = 标准 HMAC 序列
  • 模块是分离 MAC：ciphertext 长度 == plaintext 长度，tag 独立 16 字节（非 AEAD 合并）
  • tag 输出 buffer 为 16 字节（emulator fail 点观察到 alloc 16）
  • plaintext 含额外元数据字段：session_id(16B)、独立 nonce(16B)、 device_id、timestamp、seq、sv、h2_cantor、report_packet

卡住的根本原因

本地缺少 tag 阶段（SHA update）的真实运行数据。
  • ciphertext 能恢复是因为有 keystream_history（52 个 VM snapshot）+ writer_sync（store32 输出）的真实数据
  • tag 没有对应数据——所有 capture 只覆盖 keystream 生成（writer/xor/rot），无任何 SHA update 输入记录
  • dump_out 5.5GB 完整进程内存：搜 44 组样本的 tag/nonce/ciphertext/counter0/SHA-IV/K-表 全部 0 命中，确认非该加密 session 的运行数据
  • emulator 被模块的 VM 反篡改（__fastfail(0xc0000409)）挡在 tag SHA init 之前，到不了 MAC 输入 staging

4. emulator 反篡改的深入调查

已确认的反篡改机制

  • 模块自定义 IAT：直接 PE import 仅 10 个（GetModuleHandleA/jvm/winhttp 等），其余 `.rdata` 槽位由自定义 loader 运行时解析，离线无法复现
  • VM 反篡改：tag 阶段触发 __fastfail(0xc0000409)（STATUS_STACK_BUFFER_OVERRUN），由深度混淆的 VM bytecode 决策，且触发后 VM 返回垃圾栈地址、状态被破坏
  • 绕过尝试全失败：stub IsProcessorFeaturePresent/RtlCaptureContext/CRT helpers、skip int3、强制 cookie check、真实 VM context snapshot——均被同一反篡改拦截
结论：纯离线 emulator 无法绕过该反篡改到达真正的 tag SHA update。
